# Bedrock QoL Suite — v1.0.3 Release Notes

**Release Version:** `v1.0.3`  
**Compatibility:** Minecraft Bedrock Edition 1.21.0+ (`@minecraft/server` 2.10.0, `@minecraft/server-ui` 2.2.0)

---

## Highlights & Automation Upgrades

### 1. Automated Version Management in Packager
* **Smart Version Assignment:**
  * Specifying an explicit version (e.g. `npm run pack 1.0.3` or `node scripts/pack.js 1.0.3`) automatically updates `behavior_pack/manifest.json` (header, modules, dependencies), `resource_pack/manifest.json`, and `package.json`.
  * Omitting the version argument automatically scans both manifest files and increments the latest patch version by `+1`.
  * Preserves existing versions during CI/CD checks via `--no-bump`.
* **Standardized Distribution Directory:**
  * Packages are now output to clean `dist/v<version>/` directories (e.g. `dist/v1.0.3/BedrockQoL_1.0.3.mcaddon`).
  * Automated cleanup removes intermediate `.mcpack` and temporary bundles.

### 2. Discord Webhook & File Release Integration
* Added zero-dependency Discord notification dispatcher (`scripts/discord-notify.js`) via native Node `fetch`.
* **Channel Routing:**
  * Route releases to a dedicated announcements channel via `DISCORD_RELEASE_WEBHOOK`.
  * Route dev commits and build alerts via `DISCORD_DEV_WEBHOOK` or `DISCORD_WEBHOOK`.
* **Release Attachments:**
  * Direct `.mcaddon` bundle upload (`multipart/form-data`) attached to the Discord release message for 1-click import into Minecraft.
  * Direct patch notes markdown file (`BedrockQoL_v<version>_PatchNotes.md`) attached alongside the embed.
  * Rich inline patch notes preview directly inside the Discord message embed.
* **Notification Types:**
  * **Commits:** Pushes to `main` and `development` branches with author, commit hash, version, and commit message.
  * **Releases:** Official releases and development pre-release builds (Beta/Alpha) with direct download links and files.
  * **Build Failures:** Instant failure alerts with direct links to GitHub Actions logs.
* Graceful fallback when webhook repository secrets are not configured.

### 3. GitHub Actions CI/CD Pipeline
* Validates manifests, TypeScript types, and addon bundle compilation on every push and pull request.
* Dual-channel releases:
  * `main` branch → Official production releases.
  * `development` branch → Beta/Alpha development preview pre-releases.
